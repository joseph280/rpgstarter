# RPGStarter

A small Unity 6 action-RPG starter kit built around a **single editor menu** that wires the
entire project together in one click. It's a complete, playable vertical slice — movement,
ranged + melee combat, a slot inventory with a hotbar, harvesting, and crafting — assembled
from code so the whole thing is reproducible and 100% redistributable (no paid asset-store
content).

> **TL;DR to run it:** clone → `RPGStarter → Build Demo` → open **`Bootstrap.unity`** → Play.

---

## Features

- **Phantom Archer player** (Mixamo humanoid + custom controller) — camera-relative movement,
  dodge, and ranged combat with a pooled arrow system.
- **Weapons & hotbar** — Bow (arrow shot), Sword + Shield (melee), and three gathering tools
  (Hammer / Pickaxe / Axe). Equip from the hotbar (`1`–`0`).
- **Inventory UI** (`I`) — 50-slot store rendered as a **40-slot grid + 10-slot hotbar row**,
  with item icons, click-to-move/stack, and persistent selection.
- **Crafting** — a **2×2 craft grid + Craft button** inside the inventory, and a **placeable
  crafting table** you can craft, pick up, and drop into the world.
- **Harvesting** — mine rocks (Pickaxe) and chop trees (Axe) via a generic `RockMineable`
  harvest node with tool-kind gating, hit/break VFX, and pickup spawning.
- **Monster enemy** — chase / attack / death FSM with a health bar and floating damage numbers.
- **Bootstrap architecture** — a persistent `GameManager` + `SceneLoader` that additively loads
  the gameplay scene via Addressables.

Everything is generated by one menu item — **`RPGStarter → Build Demo`**.

## Controls

| Action | Input |
|---|---|
| Move (camera-relative) | `W` `A` `S` `D` |
| Aim | Mouse cursor |
| Attack / shoot | **Left Mouse** |
| Dodge | `Space` |
| Open / close inventory | `I` |
| Use / equip hotbar slot | `1` `2` … `9` `0` (10 slots) |
| Interact — pick up / place | `E` |

Bindings live in the project's input map (`Assets/_Project/Scripts/Player/PlayerInputReader.cs`
+ the `.inputactions` asset); the inventory/interact keys are serialized fields you can change
in the Inspector.

## How to play

1. **Move** around with `WASD`; the camera follows isometrically.
2. **Fight** the Monster — equip the Bow (`1`) and Left-Click to fire arrows, or Sword & Shield
   for melee.
3. **Harvest** — equip the **Pickaxe** and hit rocks, or the **Axe** and hit trees. Walk over
   the dropped pickups (`E` if prompted) to collect **Wood** and **Rock**.
4. **Open the inventory** with `I`. Your starting weapons sit in the hotbar row; materials land
   in the grid.
5. **Craft a table** — click **Wood** in the inventory, drop it into the **2×2 craft squares**,
   press **Craft**, and take the **Crafting Table** from the output slot.
6. **Place it** — move the table into a hotbar slot, select that slot, and press `E` to place it
   in the world.

## Setup

```bash
git clone https://github.com/joseph280/rpgstarter.git
cd rpgstarter
git lfs install
git lfs pull
```

Open in **Unity 6000.4+**, then:

1. Run **`RPGStarter → Build Demo`** (top menu bar). This regenerates all assets, prefabs,
   the animator, and the scene wiring, then leaves **`Bootstrap.unity`** open and pinned as the
   Play-mode start scene.
2. Press **Play**.

> **Always play from `Bootstrap.unity`.** It holds the `GameManager`, EventSystem, and the
> inventory/crafting UI, and additively loads the gameplay scene. Playing
> `Test_PlayerMovement.unity` directly gives you the player with **no HUD** (pressing `I` does
> nothing) — see [Troubleshooting](#troubleshooting).

## Architecture

**Two-scene bootstrap.** `Bootstrap.unity` is the entry point: it contains the single approved
singleton `GameManager`, a `SceneLoader`, the audio listener, the EventSystem, and the
screen-space inventory/crafting canvases. At `Start()`, `GameManager.firstSceneKey` tells the
`SceneLoader` to **additively load `Test_PlayerMovement`** (the world: floor, player, camera,
monster, scattered rocks/trees) through Addressables. The gameplay scene is never the entry
point on its own.

**Addressables in FastMode.** The gameplay scene is registered as an Addressable, and the editor
is pinned to the **FastMode** play-mode data builder so scenes resolve straight from the
AssetDatabase — no content build needed for in-editor play.

**ScriptableObject-driven, event-channel decoupled.** Weapons, abilities, items, recipes, and
enemy stats are all SOs. Gameplay systems communicate through SO event channels rather than
reaching into `GameManager` at runtime; `GameManager` is for app lifecycle only.

**Inventory/HUD.** `InventoryHUD` builds its grid + hotbar slot views at runtime from a slot-view
prefab and binds them to the player's `InventorySO`. The inventory late-binds to
`Inventory.Local` so HUD-before-player load order is handled gracefully.

## Single-menu build

The only normal menu entry is **`RPGStarter → Build Demo`**. Under the hood `Build.cs` runs a
sequence of ordered steps:

1. Primitive source assets (rock / tree / weapons / table)
2. Physics layers (Player / Enemy / Environment / projectiles)
3–14. ScriptableObject → animator → weapon roster → monster → player prefab chain
15. Standard → URP material conversion
16. Addressables sync (auto-`Repair` fallback if the Addressables internals are corrupt)
17. Scene cleanup (strip stale debug objects) + harvest-node scatter, then **open Bootstrap and
    pin it as the Play start scene**

One escape hatch is also exposed: **`RPGStarter → Repair Addressables`** — rebuilds the
Addressables config from scratch when it gets corrupt.

## Visuals: out-of-the-box vs upgraded

The kit ships with **Unity-primitive stand-ins** for rocks, trees, and the bow so the demo is
fully redistributable. Functionally everything works — chop, mine, shoot, equip, craft — but the
bow is a curved primitive stave, rocks are squashed spheres, and trees are a cylinder + sphere.

Drop in any of these **free, CC0** packs and point the kit at them for real art:

| Need | Pack | License | Where |
|---|---|---|---|
| Bow + other weapons | **Quaternius — Ultimate Modular Weapons** | CC0 | [quaternius.com](https://quaternius.com) |
| Trees + foliage | **Quaternius — Ultimate Stylized Nature** | CC0 | [quaternius.com](https://quaternius.com) |
| Rocks + props | **Quaternius — Ultimate Modular Environment** | CC0 | [quaternius.com](https://quaternius.com) |
| Alternate weapons | **Kenney — Weapon Pack** | CC0 | [kenney.nl](https://kenney.nl) |

Drop the package into `Assets/ThirdParty/<PackName>/` and either **drag-replace** the visual mesh
in the generated prefabs (`Rock_Mineable.prefab`, `Tree_Choppable.prefab`, `Weapon_Bow.asset`'s
`mainPrefab`), or change the source-prefab path constants in `Demo_PrimitiveAssets.cs`.

The **3 tools**, the **crafting table**, and the **sword + shield** (already real `.fbx` meshes)
stay as-is.

## Troubleshooting

**Pressing `I` does nothing / no inventory / no HUD.**
You're playing the wrong scene. The HUD only exists in `Bootstrap.unity`. Open it and Play (Build
Demo pins it as the Play start scene so this shouldn't happen after a build).

**`InvalidKeyException: No Location found for Key=Test_PlayerMovement` on Play.**
Addressables lost the scene registration or isn't in FastMode. Run **`RPGStarter → Repair
Addressables`** (or re-run Build Demo), which re-registers the scenes and restores the FastMode
data builder.

**Inventory opens but slots/icons are missing.**
The HUD's `slotViewPrefab` reference went stale. Re-run **Build Demo** — the slot-view prefab is
built idempotently so scene references stay valid across rebuilds.

**Bow/weapon orientation looks off in the hand.**
Tune `mainLocalPos` / `mainLocalEuler` / `mainLocalScale` on the weapon's SO
(`ScriptableObjects/Weapons/Weapon_*.asset`) in the Inspector — these survive rebuilds.

**Compile errors after pulling.**
Let Unity finish importing/compiling, then re-run Build Demo. The editor assemblies must be green
before the build steps will run.
